我们做过一个假设：Agent 表现不够好，是因为工具不够多。于是不断加工具——浏览器、文件、搜索、邮件。工具加到第九个的时候，成功率并没有明显上升。

真正让它变聪明的，是**让它记住上一次发生了什么**。

## 第一版：把对话全存下来

最朴素的想法：既然要记忆，那就把每次执行的完整对话存进数据库，下次全量塞进 prompt。

结果很快崩了：

- 一次任务几千 token，塞三次就顶到上下文上限；
- 大量无关内容稀释了关键信息；
- 早期的一条错误经验，会影响后面十次正确判断。

**结论：记忆不等于日志。** 把原始流水账塞回去，等于让 Agent 每次都在噪音里找信号。

## 第二版：结构化经验 + 关键词检索

改成只存"经验"：任务类型、采取的动作、结果（成功/失败）、关键上下文。检索用关键词匹配。

代码大概是这样：

```ts
interface Experience {
  taskType: string
  action: string
  result: 'success' | 'failure'
  context: string
  note: string
}

function recall(query: string): Experience[] {
  // 关键词命中 + 结果加权
  return store
    .filter((e) => e.taskType.includes(query))
    .sort((a, b) => score(b) - score(a))
    .slice(0, 5)
}
```

成功率上去了，但遇到一个尴尬问题：**语义一样、词不一样的经验检索不到。**

用户说"发消息给张三"，经验里存的是"向联系人发送微信"，关键词完全不匹配。

## 第三版：语义检索 + 失败优先

最后改成了两条规则：

1. **用向量检索代替关键词**，让语义相近的经验能被召回；
2. **失败经验权重高于成功经验**。成功路径有很多条，失败陷阱却总是那几个——避开陷阱的收益更大。

第二条是这次最大的收获。我们统计过：在所有召回的经验里，失败经验虽然只占三成，但避免了六成以上的重复错误。

> 让 Agent 少犯错，比教它多做对一件事，性价比高得多。

## 还剩下的坑

- **经验污染**：一次异常环境导致的失败，如果被当成普遍规律，会让 Agent 变得过度保守。我们加了"置信度"和"失效时间"。
- **经验膨胀**：什么都记，等于什么都没记。现在只存"非显然"的经验——那些不查就一定会踩的坑。
- **跨任务迁移**：目前经验只在同类任务内复用，跨类型迁移还没找到好办法。

## 一句话总结

如果你也在做 Agent，我的建议是：**先把记忆做好，再考虑加工具。** 工具决定它能做什么，记忆决定它能不能做对。
