好排版是隐形的。读者不会说"这篇文章排版真好"，但排版糟糕时，他会说"看不下去"。

下面这份清单，是我每次调文章样式时逐条过的。

## 1. 行宽控制在 34–40 个汉字

一行太长，眼睛换行时容易跳错；太短，视线来回扫，节奏碎。

```css
/* 大约 68ch 的宽度，中英混排都舒服 */
.prose { max-width: 42rem; }
```

实测：手机上基本不会超，问题主要在宽屏——别忘了给正文容器设最大宽度。

## 2. 行高至少 1.7

中文没有西文那种高低起伏的轮廓，字块更"实"，需要更多行间距来透气。

- 正文：`1.75–1.85`
- 标题：`1.25–1.35`（标题行高要收紧，否则会散）
- 代码、注释：`1.6`

## 3. 段落间距 > 行间距

这是最容易被忽略的一条。如果段间距等于行间距，整篇文章会糊成一块。

```
行间距: 1.8em  →  段间距: 1.4em（相对字号）
```

判断方法：遮住文字只看形状，能不能一眼看出分了几段？看不出就加大。

## 4. 层级靠"字号 + 字重 + 空间"，不要只靠颜色

三级标题只靠颜色区分，在暗色模式下很容易失效。稳妥的做法是让每级标题在**字号和上下留白**上都有差异。

## 5. 中文正文不要用纯黑

`#000` 在白底上对比过强，长时间阅读会疲劳。用 `#1f1d1a` 这类接近黑但带一点暖度的颜色，观感柔和很多。

同理，暗色模式也不要用纯白，用 `#ece9e3`。

## 6. 中英混排加一点字距

中文里夹英文时，英文两侧常常贴得太紧：

```css
.prose { letter-spacing: 0.01em; }
```

效果很微妙，但去掉之后会明显感觉"挤"。

## 7. 引用、代码、列表各有各的样子

- **引用**：左侧一条细线 + 衬线体 + 稍大字号，别做成灰色斜体了事；
- **代码**：背景不要太浅，文字不要太细，行高给足；
- **列表**：符号和文本之间留够距离，多行列表项注意悬挂缩进。

## 8. 移动端单独检查

至少看三件事：代码块会不会横向溢出、表格要不要改成滚动、标题在 320px 下会不会断得难看。

## 最后

排版没有"最佳参数"，只有"更适合这个场景的参数"。但上面这八条里的每一条，违反都会造成明确的阅读障碍——先把错误答案排除掉，剩下的就是审美问题了。
